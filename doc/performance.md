# 記憶體與執行速度調整

## 縮圖工作區

- 虛擬網格只掛載可視列及前後兩列，保留「載入更多／全部載入」與跨捲動選取。
- 前端縮圖 LRU 同時限制 200 筆及 16 MiB（依 UTF-16 字串長度保守估計）；未開始的離屏請求直接移除，最多同時 3 個後端請求。
- 後端縮圖直接串流解碼，只暫存讀取尺寸所需的前綴；同時解碼的總像素不超過 5,000 萬。
- 磁碟縮圖使用 LRU 索引；每次寫入維持最多 1,200 筆、256 MiB，只在初始化掃描目錄。外部刪除快取時同步移除索引。
- 縮圖版本包含來源大小與修改時間；macOS 另比對 inode 與 change time。解碼期間來源變更時不寫入舊版本快取；快取讀取在同一 FD 上限制最多 16 MiB。
- 影音解壓及轉檔快取比對來源檔案識別、大小、修改時間；來源更新時重建，已開啟的舊讀取器仍可完成讀取。
- 媒體清理先取消準備與複製，再等待項目鎖釋放；HTTP 只持鎖至成功開檔，串流讀取不占用準備鎖。
- 像素預算不是程序 RSS 上限：解碼器工作區、16-bit 圖片及 GC 尚未回收的物件仍會占用記憶體。仍使用 Go 完整解碼，尚未加入平台限定的降採樣解碼器。

## 主圖傳輸

`LoadImage*` 的 `ImagePayload.dataUri` 可為 `/image/<id>?v=...` 本機網址。保留欄位名稱以維持前端結構；不要假設一定是 Base64。

本機圖片由 HTTP 串流傳輸，保留 128 MiB 檔案與 5,000 萬像素限制，GET／HEAD／Range 與 ETag。端點只接受已註冊的圖片 ID。壓縮檔圖片仍有完整驗證緩衝區，最多並行 2 筆；原圖不再經由 Wails 傳輸 Base64。

前端只解碼目前顯示的圖片，切圖取消舊要求，背景僅預備相鄰圖片的網址／標頭。剪貼簿仍可輸出 PNG，只有文字備援時才轉回 Data URI。

## 壓縮檔

- ZIP：LRU 最多 4 個中央目錄索引；每個最多 20,000 個項目與約 8 MiB 的標頭資料估計值。超限時不保留索引。
- TAR／TGZ：最多 2 份、每份最多 256 MiB 的私有暫存內容與 20,000 個索引項目。第一次讀取建立索引會多花時間與磁碟 I/O，後續以位移讀取；超限或稀疏檔案回到原串流方式。暫存檔不依壓縮檔中的路徑解壓至目錄。
- 大小、修改時間或檔案識別改變時快取失效；清空圖庫及結束應用程式會清理快取。使用中的 reader 關閉後才釋放其資源。

## 圖庫

展開狀態與選取獨立儲存，不觸發整棵樹的 JSON 寫入。掃描約每 100 ms 批次更新畫面，同批結果只遍歷一次樹；未變更分支保留原參考。忽略未支援的檔案時不額外取得檔案資訊。
